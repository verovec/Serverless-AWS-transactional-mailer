## Data flow

```
  Client            sqs.send_message(QueueUrl, MessageBody=json)
     |
  SQS queue         standard queue, created by hand; URL and ARN stored in SSM
     |
  Event source      batchSize 10, maximumBatchingWindow 60 s, ReportBatchItemFailures
     |
  send-email        Python 3.9, 512 MB, timeout 900 s, env SENDINBLUE_API_KEY and QUEUE_URL
     |
  Sendinblue        TransactionalEmailsApi.send_transac_email(template_id, to, params)
```

The handler takes `event["Records"][0]`, parses its `body` as JSON, deletes the message with
`sqs.delete_message(QUEUE_URL, receipt_handle)`, then calls the API. It needs `sqs:DeleteMessage`
on the queue in addition to the receive permissions the framework grants to the event source.
Because the deletion happens before the API call, an `ApiException` is raised to CloudWatch but
the message is not redelivered. The other records of a batch, if any, are ignored by the code.

## What the stack creates

| Resource | From |
|----------|------|
| Lambda function `send-email` | `functions.send_email` |
| Event source mapping on the queue `${ssm:/QUEUE_ARN}` | `functions.send_email.events[0].sqs` |
| IAM execution role with CloudWatch Logs and SQS receive permissions | generated by the framework |
| CloudWatch Logs group `/aws/lambda/send-email` | generated by the framework |
| API Gateway API key `myApiKey` | `provider.apiGateway.apiKeys` |

The stack is named `serverless-stack` and the deployment packages go to `${ssm:/S3_BUCKET}`
under the `serverless/` prefix with public access blocked. The API key is a leftover of the
template this repository started from: there is no `http` event, so no REST API is created and
the key is unused.

## Configuration

| Name | Kind | Role |
|------|------|------|
| `S3_BUCKET` | SSM `SecureString` | Deployment bucket, created beforehand in `eu-west-1` |
| `QUEUE_URL` | SSM `SecureString`, then Lambda env | URL used by the handler to delete the message |
| `QUEUE_ARN` | SSM `SecureString` | ARN of the same queue, wired as the event source |
| `SENDINBLUE_API_KEY` | SSM `SecureString`, then Lambda env | v3 API key of the Sendinblue account |
| `API_KEY_SERVERLESS` | SSM `SecureString` | Value of the unused API Gateway key |
| `provider.region` | `serverless.yml` | `eu-west-1` |
| `provider.runtime` | `serverless.yml` | `python3.9` |

The function reads `SENDINBLUE_API_KEY` and `QUEUE_URL` from its environment; both are injected
by `serverless.yml` from SSM. Sendinblue became Brevo in 2023; the v3 API and `sib-api-v3-sdk`
still work, but new keys are created in the Brevo console.
